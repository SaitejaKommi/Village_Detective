# Work Division

## Roles

| Person | Focus | Owns |
| --- | --- | --- |
| **Person A (you)** | Frontend | `client/`, UI/UX, Phaser scenes, client networking |
| **Person B (friend)** | Backend | `server/`, agents, LLM layer, DB, auth, game logic |
| **Both** | Contract | `shared/types.ts`, docs, README, video |

Detailed task lists are on the Frontend Plan and Backend Plan pages.

## The contract

`shared/types.ts` defines every WebSocket message and the world state shape.

- Freeze it in the first 30 minutes.
- After that, any change needs a message in the team chat and the other person's OK before merging.
- Person A builds against the mock server, Person B tests with a simple script or `wscat`, so neither blocks the other.

## If someone finishes early

**Frontend done first (Person A helps backend):**

1. Write `personas.json` content: names, personalities, secrets, goals, alibis.
2. Write clue text and the murder intro/reveal text.
3. Build the debug overlay's data format with Person B.
4. Write integration tests for WebSocket messages.
5. Tune prompts: run NPC conversations and fix weak or repetitive replies.

**Backend done first (Person B helps frontend):**

1. Build the notebook panel and reveal screen.
2. Add sound effects and `speechSynthesis` voices.
3. Create or tweak map layouts and room data.
4. Help with the Phaser collision and camera issues.
5. Prepare video-friendly features: debug overlay content and a "God view".

**Both done early:** pick stretch goals from the plan pages, starting with the one that makes the best video moment (usually the debug overlay or a contradiction caught live).

## Communication

- **Chat:** one Discord or WhatsApp group. Post short updates when you start and finish a block.
- **Quick call:** 5-minute sync at each milestone (0:30, 2:00, 3:00, 4:00).
- **Blockers:** post immediately. Do not wait for the next milestone.
- **Decisions:** write important ones in the chat, then add them to the relevant page. Log them on the Updates and Comms page.

## Git workflow

- **Repo:** one GitHub repo (monorepo with npm workspaces).
- **Branches:**
    - `main`: always runs; protected from direct pushes after setup
    - `feat/client-<name>` for Person A
    - `feat/server-<name>` for Person B
    - `feat/shared-types` for contract changes
- **Commits:** small and frequent. Format: `client: add dialogue box`, `server: add Zod action schema`.
- **Pull requests:** open a PR for each feature. Keep them small.
- **Review:** the other person reviews and merges. A quick pass is enough: it builds, it runs, and it does not break the contract. During the 5-hour challenge, self-merge is allowed if the other person is busy, but tell them in chat.
- **Conflicts:** `shared/types.ts` is the most likely file to conflict. Change it on its own small branch and merge it fast.
- **Secrets:** never commit `.env`. Only `.env.example`.
